# سایت کتاب «راز داوینچی» (قالب قابل‌تکثیر)

همه‌ی متن‌ها **نمونه (placeholder)** هستند. هیچ نقل‌قول، نظر یا منبعی واقعی نیست؛ همه را خودتان جایگزین کنید.

## ساختار
- `index.html` صفحه‌ی اصلی | `css/main.css` ظاهر (رنگ‌ها و فونت‌ها در بالای فایل)
- `js/app.js` منطق سایت | `js/comments.js` ورود و دیدگاه‌ها (Supabase)
- `content/book.json` شناسه‌ی کتاب، امتیاز (۰ تا ۵)، جلد، بخش‌های پنهان، تنظیمات Supabase
- `content/fa.json` و `content/en.json` متن فارسی و انگلیسی | `supabase.sql` ساخت پایگاه داده

## ویرایش محتوا
فقط فایل‌های `content/*.json` را ویرایش کنید. امتیاز فعلی (۳٫۵) نمونه است؛ در `book.json` عوض کنید.
- بخش را پنهان کنید: نام آن را در `"hidden"` بنویسید، مثلاً `["characters","context"]`.
- بخش اسپویلی: `"spoiler": true` در همان بخش.
- پژوهش: `"status": "needs"` یا `"reviewed"`. جلد: عکس را در `assets/images/` بگذارید و `"cover": "assets/images/cover.jpg"` بنویسید.
- مراقب ویرگول و گیومه‌ی JSON باشید؛ بعد از ویرایش، سایت را باز کنید تا مطمئن شوید بالا می‌آید.

## انتشار روی GitHub Pages (بدون خط فرمان)
1. در GitHub یک repository جدید بسازید (مثلاً `da-vinci-code`).
2. Add file > Upload files؛ **محتوای** پوشه را (نه خود پوشه را) آپلود و Commit کنید.
3. Settings > Pages > Source: `Deploy from a branch` > Branch: `main` و `/ (root)` > Save.
4. بعد از چند دقیقه آدرس `https://USERNAME.github.io/REPO/` فعال می‌شود.
5. برای به‌روزرسانی: فایل را در GitHub باز کنید، مداد (Edit)، تغییر، Commit.
همه‌ی مسیرها نسبی‌اند و زیر آدرس مخزن کار می‌کنند.

## راه‌اندازی Supabase (برای ورود و دیدگاه)
1. در supabase.com پروژه بسازید. 2. SQL Editor: محتوای `supabase.sql` را اجرا کنید.
3. Project Settings > API: **Project URL** و **publishable (anon) key** را در `content/book.json` بگذارید.
4. Authentication > URL Configuration: آدرس سایت را در Site URL بگذارید.
5. Authentication > Providers > Email: اگر «Confirm email» روشن باشد، کاربر بعد از ثبت‌نام باید ایمیلش را تأیید کند.
6. یک‌بار در سایت ثبت‌نام کنید، سپس خط آخر SQL (admin) را با ایمیل خودتان اجرا کنید.
7. دیدگاه‌ها با وضعیت `pending` ثبت می‌شوند؛ در Table Editor وضعیت را به `approved` ببرید (یا `hidden` برای حذف از نمایش).

**کلید عمومی در برابر کلید محرمانه:** کلید publishable/anon برای مرورگر است و حفاظتش با سیاست‌های RLS است. کلید `service_role` (secret) دسترسی کامل می‌دهد و **هرگز** نباید در این سایت یا GitHub قرار بگیرد.

## ساخت سایت برای کتاب دیگر
1. مخزن را Copy/Fork یا فایل‌ها را در مخزن جدید آپلود کنید.
2. `content/*.json` را عوض کنید؛ در `book.json` یک `id` تازه و یکتا بگذارید (مثلاً `1984`).
3. در Supabase یک ردیف جدید برای کتاب بسازید: `insert into public.books values('1984','Title');`
4. رنگ و فونت را در بالای `css/main.css` تغییر دهید. همان پایگاه داده برای همه‌ی کتاب‌ها استفاده می‌شود و دیدگاه‌ها با `book_id` جدا می‌مانند.
(نکته: کد در هر مخزن کپی می‌شود؛ هزینه‌ی ایستا بودن GitHub Pages همین است.)
