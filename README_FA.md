# ژورنال مطالعه‌ی کتاب — راهنمای فارسی

این پروژه یک وب‌سایت ساده و دوزبانه (فارسی/انگلیسی) برای ثبت تجربه‌ی خواندن یک کتاب است. برای هر کتاب یک سایت جداگانه می‌سازید. **همه‌ی محتوا فقط در یک فایل است: `data/content.json`.** لازم نیست برنامه‌نویسی بلد باشید.

## ۱. ساختار فایل‌ها

| فایل / پوشه | کاربرد |
|---|---|
| `data/content.json` | **تنها فایلی که معمولاً ویرایش می‌کنید**: مشخصات کتاب، یادداشت‌ها، ایده‌ها، قسمت‌های صوتی، نقل‌قول‌ها |
| `assets/images/` | تصویر جلد و تصویر اختیاری قسمت‌های صوتی |
| `css/style.css` | ظاهر سایت (رنگ‌ها در بخش `:root` بالای فایل) |
| `js/app.js` | عملکرد سایت (زبان، تم، جستجو، اشتراک‌گذاری) |
| `index.html`، `notes.html`، `note.html`، `ideas.html`، `audio.html`، `quotes.html` | صفحه‌ها؛ نیازی به ویرایش ندارند |
| `.nojekyll` | فایل خالی؛ نگهش دارید |

## ۲. پیش‌نمایش روی کامپیوتر (مهم)

اگر `index.html` را با دابل‌کلیک باز کنید، مرورگر اجازه‌ی خواندن `content.json` را نمی‌دهد و پیام خطا می‌بینید. این رفتار عادی مرورگر است، نه خراب بودن سایت. دو راه دارید:

1. ساده‌ترین راه: تغییرات را در گیت‌هاب ذخیره کنید و سایتِ منتشرشده را ببینید.
2. اگر پایتون نصب است: در پوشه‌ی پروژه دستور `python3 -m http.server 8000` را اجرا کنید و `http://localhost:8000` را باز کنید.

## ۳. نکات مهم نوشتن JSON (جلوگیری از خطا)

- هر متن داخل `"گیومه‌ی دوتایی صاف"` است (نه « » و نه “ ”).
- بین دو مورد پشت‌سرهم **ویرگول** بگذارید، اما **بعد از آخرین مورد نه**.
- داخل یک متن، گیومه‌ی دوتایی صاف ننویسید؛ از « » استفاده کنید.
- برای پاراگراف تازه داخل یک متن، بنویسید `\n\n` (نه Enter واقعی).
- هر `id` باید **یکتا** باشد و فقط از حروف انگلیسی، عدد، `-` و `_` ساخته شود (مثلاً `note-3`). بعد از انتشار، id را عوض نکنید؛ چون پیوندهای اشتراک‌گذاری‌شده به آن وابسته‌اند.
- تاریخ‌ها را به شکل `"2026-10-18"` بنویسید.
- قبل از ذخیره، متن را در سایت <https://jsonlint.com> بچسبانید تا خطاها را نشان دهد. اگر `id` تکراری یا نامعتبر باشد، خود سایت هم یک هشدار نمایش می‌دهد.

## ۴. کارهای رایج

### ۴.۱ تغییر عنوان و نویسنده‌ی کتاب
در `data/content.json` بخش `"book"` را ویرایش کنید:
```json
"title":  { "fa": "عنوان فارسی", "en": "English title" },
"author": { "fa": "نام نویسنده", "en": "Author name" },
"intro":  { "fa": "معرفی کوتاه…", "en": "Short introduction…" }
```

### ۴.۲ تعویض تصویر جلد
تصویر خود را (بهتر است عمودی و با نسبت ۳ به ۴، مثلاً ۶۰۰×۸۰۰ پیکسل، با فرمت jpg/png/webp/svg و حجم کم) در `assets/images/` آپلود کنید و نام آن را در `"cover"` بنویسید:
```json
"cover": "assets/images/my-cover.jpg"
```
متن جایگزین تصویر (برای دسترس‌پذیری) در `"coverAlt"` است.

### ۴.۳ افزودن یادداشت
یک بلوک تازه به فهرست `"notes"` اضافه کنید (بین بلوک‌ها ویرگول بگذارید):
```json
{
  "id": "note-3",
  "title":   { "fa": "عنوان یادداشت", "en": "Note title" },
  "date": "2026-10-20",
  "chapter": { "fa": "فصل ۳", "en": "Chapter 3" },
  "preview": { "fa": "خلاصه‌ی کوتاه", "en": "Short preview" },
  "text": {
    "fa": "پاراگراف اول.\n\nپاراگراف دوم.",
    "en": "First paragraph.\n\nSecond paragraph."
  },
  "tags": { "fa": ["موضوع"], "en": ["topic"] },
  "related": ["note-1"]
}
```
`related` فهرست idِ یادداشت‌های مرتبط است و اختیاری است. پیوند ثابت این یادداشت: `note.html?id=note-3`.

### ۴.۴ افزودن ایده یا پرسش
به فهرست `"ideas"`:
```json
{
  "id": "idea-2",
  "title":       { "fa": "عنوان", "en": "Title" },
  "summary":     { "fa": "خلاصه", "en": "Summary" },
  "description": { "fa": "توضیح کامل", "en": "Full description" },
  "date": "2026-10-20",
  "chapter": { "fa": "فصل ۲", "en": "Chapter 2" },
  "tags": { "fa": ["پرسش"], "en": ["question"] }
}
```
پیوند ثابت: `ideas.html#idea-2`.

### ۴.۵ افزودن نقل‌قول
به فهرست `"quotes"`. **متن را دقیقاً از کتاب بنویسید؛ سایت هیچ نقل‌قولی نمی‌سازد.**
```json
{
  "id": "quote-2",
  "title":  { "fa": "برچسب کوتاه (برای جستجو)", "en": "Short label (for search)" },
  "text":   { "fa": "متن دقیق نقل‌قول", "en": "" },
  "source": { "fa": "نام نویسنده یا منبع", "en": "" },
  "page": "112",
  "reflection": { "fa": "تأمل شخصی (اختیاری)", "en": "" }
}
```
`title` برچسبی است که خودتان می‌نویسید؛ جستجو فقط روی همین عنوان‌ها انجام می‌شود. `page`، `reflection` و `title` اختیاری‌اند (می‌توانید خالی `""` بگذارید). پیوند ثابت: `quotes.html#quote-2`.

### ۴.۶ افزودن قسمت صوتی
```json
{
  "id": "episode-2",
  "title":       { "fa": "عنوان قسمت", "en": "Episode title" },
  "description": { "fa": "توضیح", "en": "Description" },
  "date": "2026-10-20",
  "image": "assets/images/episode-2.jpg",
  "audioUrl": "https://example.com/files/episode-2.mp3"
}
```
- فایل‌های صوتی را معمولاً **در گیت‌هاب نگذارید** (حجم زیاد)؛ آن‌ها را در یک سرویس میزبانی فایل بگذارید.
- `audioUrl` باید **پیوند مستقیم به خود فایل** (مثلاً پایان‌یافته با `.mp3`) باشد. پیوند «صفحه‌ی اشتراک‌گذاری» (مثل صفحه‌ی پخش‌کننده‌ی گوگل‌درایو یا دراپ‌باکس) معمولاً کار نمی‌کند، چون مرورگر به‌جای فایل، یک صفحه‌ی وب دریافت می‌کند.
- سرویس باید اجازه‌ی پخش مستقیم بدهد؛ پس از انتشار، پخش را روی خود سایت امتحان کنید.
- اگر `audioUrl` خالی باشد یا فایل بارگذاری نشود، به‌جای پخش‌کننده‌ی خراب، پیام توضیحی نمایش داده می‌شود. `image` اختیاری است (می‌تواند `""` باشد).

### ۴.۷ ویرایش نسخه‌ی فارسی و انگلیسی
هر متن دو کلید `fa` و `en` دارد. هر دو را پر کنید یا یکی را خالی بگذارید. **ترجمه‌ی خودکار انجام نمی‌شود.** اگر نسخه‌ی زبان انتخاب‌شده خالی باشد، نسخه‌ی زبان دیگر نمایش داده می‌شود و کنار آن برچسب `[فارسی]` یا `[English]` می‌آید.

### ۴.۸ حذف نمونه‌ها
ورودی‌های دارای `"placeholder": true` نمونه‌اند و در سایت برچسب «نمونه» دارند. آن‌ها را پاک کنید یا متنشان را عوض کنید و خط `placeholder` را بردارید. اگر فهرستی را کاملاً خالی کنید (`"notes": []`)، سایت پیام «هنوز موردی ثبت نشده» نشان می‌دهد.

## ۵. انتشار در GitHub Pages

۱. در <https://github.com> وارد حساب خود شوید و **New repository** بزنید؛ نامی انگلیسی بدهید (مثلاً `my-book-journal`) و آن را **Public** بگذارید.
۲. در صفحه‌ی مخزن، **Add file ← Upload files** را بزنید. محتوای پوشه‌ی پروژه را (نه خود پوشه را) بکشید و رها کنید؛ حتماً پوشه‌های `css`، `js`، `data`، `assets` و فایل `.nojekyll` هم باشند. سپس **Commit changes**.
   - اگر فایل `.nojekyll` در آپلود دیده نشد، با **Add file ← Create new file** فایلی به همین نام (خالی) بسازید.
۳. **Settings ← Pages**: در بخش Source گزینه‌ی **Deploy from a branch** و شاخه‌ی `main` و پوشه‌ی `/ (root)` را انتخاب و **Save** کنید.
۴. بعد از یکی دو دقیقه، نشانی سایت در همان صفحه نشان داده می‌شود، مثلاً `https://نام‌کاربری.github.io/my-book-journal/`.

**برای ویرایش بعدی:** در گیت‌هاب فایل `data/content.json` را باز کنید ← آیکن مداد (Edit) ← تغییر دهید ← **Commit changes**. معمولاً چند دقیقه بعد در سایت دیده می‌شود (اگر تغییر دیر آمد، صفحه را با Ctrl+F5 تازه کنید). برای تصویر جدید: پوشه‌ی `assets/images` ← Add file ← Upload files.

همه‌ی نشانی‌ها نسبی‌اند، پس سایت هم روی کامپیوتر و هم زیر نشانی پروژه (`/نام-مخزن/`) کار می‌کند.

## ۶. استفاده‌ی دوباره برای کتاب‌های دیگر
برای هر کتاب یک مخزن جدید بسازید و همین فایل‌ها را در آن بگذارید؛ سپس فقط `content.json` و تصویر جلد را عوض کنید.

## ۷. محدودیت‌ها (بخوانید)

- GitHub Pages فقط میزبانی ایستا است: پایگاه‌داده، ورود با رمز، یا داشبورد آپلود ندارد. محتوا فقط با ویرایش فایل‌های مخزن تغییر می‌کند.
- سایت برای بازدیدکننده «فقط‌خواندنی» است. تغییر تم، زبان، جستجو و اشتراک‌گذاری فقط در مرورگر خود او اثر دارد و در سایت ذخیره نمی‌شود.
- **مخزن عمومی است؛ یادداشت محرمانه، رمز یا اطلاعات خصوصی در آن نگذارید.**
- جستجو فقط در عنوان‌ها انجام می‌شود.
- تاریخ‌ها در حالت فارسی با تقویم شمسی (و ارقام فارسی) نمایش داده می‌شوند، اما در فایل به شکل میلادی `YYYY-MM-DD` نوشته می‌شوند.
- فونت سفارشی بارگذاری نمی‌شود (برای سرعت و بدون وابستگی بیرونی). اگر فونت «وزیرمتن» روی دستگاه نصب باشد از آن استفاده می‌شود، وگرنه فونت‌های پیش‌فرض سیستم.
- دکمه‌ی اشتراک‌گذاری در دستگاه‌هایی که از Web Share پشتیبانی می‌کنند منوی اشتراک را باز می‌کند؛ در غیر این صورت پیوند کپی می‌شود، و اگر مرورگر اجازه‌ی کپی ندهد، پیوند در یک پنجره برای کپی دستی نمایش داده می‌شود.
- پخش صوت به در دسترس بودن و تنظیمات سرویس میزبان فایل شما بستگی دارد.
